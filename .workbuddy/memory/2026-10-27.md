## 修复：深睡后按按键唤不醒（ai-passport / ESP32-C3）
- 现象：息屏 10 分钟进 deep sleep 后，按 UP/DOWN/OK 无任何反应，屏幕不亮。
- 结论：**根本没醒，不是醒了不亮屏**。deep sleep 唤醒=整芯片复位，醒来必然重跑 `AiPassportBoard` 构造函数、重新 init 屏并 `RestoreBrightness()`，不存在"醒了仍黑屏"的路径。
- 根因：`AiPassportBoard::EnterDeepSleep()` 用 `gpio_wakeup_enable()` + `esp_sleep_enable_gpio_wakeup()` —— 这两个只服务 **light sleep**，`esp_deep_sleep_start()` 完全忽略，等于零唤醒源，只能靠 RST/上电恢复。
- **API 名字坑（更正 2026-10-27 早前的猜测）**：IDF 6.x **没有** `esp_deep_sleep_enable_gpio_wakeup()`。核对官方 `components/esp_hw_support/include/esp_sleep.h`（v6.0.1 / v6.1）后确认：
  - deep sleep GPIO 唤醒 = `esp_sleep_enable_gpio_wakeup_on_hp_periph_powerdown(uint64_t gpio_pin_mask, esp_sleep_gpio_wake_up_mode_t mode)`，枚举 `ESP_GPIO_WAKEUP_GPIO_LOW/HIGH`，守卫宏 `SOC_GPIO_SUPPORT_HP_PERIPH_PD_SLEEP_WAKEUP`。
  - ESP32-C3 `soc_caps.h`：`SOC_GPIO_SUPPORT_HP_PERIPH_PD_SLEEP_WAKEUP=1`、`SOC_RTCIO_PIN_COUNT=0`、**没有** `SOC_PM_SUPPORT_EXT1_WAKEUP`（C3 不支持 ext0/ext1）。
  - `esp_sleep_enable_ext1_wakeup` 仍存在但已标记 6.0 弃用，替代 `esp_sleep_enable_ext1_wakeup_io`；非 ESP32 芯片的 `ESP_EXT1_WAKEUP_ALL_LOW` 也弃用，改 `ANY_LOW`。
  - `esp_sleep_get_wakeup_cause()` 在 6.x 弃用，用 `uint32_t esp_sleep_get_wakeup_causes()` 位图。
- 改动 1（`main/boards/folotoy/ai-passport/ai_passport_board.cc`）：
  - `EnterDeepSleep()`：GPIO0（三个电阻梯按键共用，按下 0/300/595 mV，均 < 0.25×VDD=0.825V）改为 `gpio_config()` 纯输入（板上已有 10k 外部上拉，禁用内部上拉）→ `esp_sleep_enable_gpio_wakeup_on_hp_periph_powerdown(1ULL<<0, ESP_GPIO_WAKEUP_GPIO_LOW)`，非 C3 板卡走 `#elif` 的 ext1 分支。
  - 构造函数开头打印 `esp_sleep_get_wakeup_causes()`，重启即可判断"唤醒成功 vs 从未唤醒"。
- 改动 2（`main/display/lcd_display.cc`）：`screen_off_seconds_` 到阈值后不再清零，而是 pin 在 `kDeepSleepSeconds`，这样 `EnterDeepSleep()` 因 `CanEnterSleepMode()==false`（有音频/通话）提前返回时下一 tick 立刻重试，而不是再等 10 分钟。
- 验证方式：临时把 `kDeepSleepSeconds` 改 20s → 进深睡 → 按键 → 串口应出现 `ESP-ROM:esp32c3` 启动日志 + `Boot after sleep, wakeup causes: 0x..`。
- 遗留：深睡前只关背光、未给 ST7789 发 SLPIN，屏静态电流仍在 mA 级；唤醒是整机重启（WiFi 重连 + UI 重建约数秒），如需"秒醒"应改用 light sleep。

## 深睡省电补强（同日，用户要求保留 deep sleep 断 WiFi）
- 用户明确要 deep sleep（必须断 WiFi 省电），因此不采用 light sleep 方案。**deep sleep 无需代码断 WiFi**：睡眠时序会切断 radio 电源域；调 `esp_wifi_stop()` 只会多一次断连往返，已在注释里写明不要加。
- 上一条"遗留"已修，`AiPassportBoard::EnterDeepSleep()` 现在按顺序做：
  1. 背光 `SetBrightness(0)`（原有）
  2. **面板进睡眠**：新增成员 `display_io_` / `display_panel_`（`InitializeDisplay()` 里保存），深睡前 `esp_lcd_panel_disp_on_off(panel,false)`（0x28 DISPOFF）+ `esp_lcd_panel_io_tx_param(io, 0x10, NULL, 0)`（SLPIN）+ 10ms。ST7789 只要没 SLPIN，电荷泵/栅极驱动会持续吃几 mA，比 C3 本体（µA 级）大几个数量级。
  3. **关 codec**：`GetAudioCodec()->EnableOutput(false)` + `EnableInput(false)`；两者都 false 时 `Es8311AudioCodec` 会 `esp_codec_dev_close/delete`。该板 `AUDIO_CODEC_PA_PIN = GPIO_NUM_NC`，功放使能没接 MCU，只能关 codec 本身。
  4. 配置 GPIO0 深睡唤醒源 → `esp_deep_sleep_start()`
- 唤醒可恢复性：`DISPLAY_RST_PIN` 是 NC（软复位），重启时 `esp_lcd_panel_reset()` 发 0x01 SWRESET、`esp_lcd_panel_init()` 发 0x11 SLPOUT，SLPIN 状态必然解除，不会黑屏。

### 深睡唤醒实测结果（22:42，20s 测试版）
- **唤醒成功，功能验证通过**。证据链：串口节点 `/dev/cu.usbmodem13101` 在设备深睡时**完全消失**（`ls /dev/cu.*` 只剩 Bluetooth/debug-console）→ 用户按键 → 节点重新枚举 → 脚本抓到完整启动日志 → 屏幕亮 → 用户当场用语音对话成功（日志 `Application: >> 你好呀。` / `<< 你好呀！我是小智…`，状态机 listening→speaking 正常）。
- ⚠ **`Boot after sleep, wakeup causes: 0x1` 是误导**：0x1 = bit0 = `ESP_SLEEP_WAKEUP_UNDEFINED`，恰恰说明"不是深睡唤醒"。原因是我用 pyserial 打开 `/dev/cu.usbmodem*` 时设置 DTR/RTS 触发了 `rst:0x15 (USB_UART_CHIP_RESET)`，把真正的唤醒启动**二次复位覆盖**了。真实唤醒原因（应为 `ESP_SLEEP_WAKEUP_GPIO` = bit7 = 0x80）在 USB 枚举完成前就已打印，主机端必然丢。
- **重要硬件事实**：ESP32-C3 的 USB Serial/JTAG 属于 HP 外设，**深睡时掉电 → USB 断开 → 主机侧 `/dev/cu.usbmodem*` 消失**，唤醒后重新枚举（编号可能变）。所以"深睡期间盯着串口看"永远看不到东西；且不要用 pyserial 打开该端口（会多发一次 USB_UART_CHIP_RESET）。想抓真实唤醒原因只能：把 cause 写入 NVS 事后读、或上屏显示、或在打印前加延时等 USB 枚举完成。

## 功耗基线（估算，待实测）
- 亮屏：C3 空闲 12~20 mA + WiFi modem sleep（beacon 102.4 ms / DTIM=1，`LOW_POWER/MAX_MODEM`）5~15 mA + ES8311/I2S 5~10 mA + ST7789 2~3 mA + 背光（240×320，亮度按 50~75% 估）20~60 mA ≈ **50~100 mA**。
- 息屏（只关背光，芯片仍醒、WiFi 保持）：**约 25~40 mA** —— 只省掉背光，量级几乎不变。
- 深睡（新代码：背光 0 + ST7789 DISPOFF/SLPIN + ES8311 close + radio 断电）：C3 5~10 µA + 面板 10~20 µA + codec 待机 20~50 µA + CW2017 15 µA，**理论 100~200 µA**，实测受 LDO 静态、背光升压 IC、上拉电阻影响，可能 200~400 µA。
- 结论：息屏→深睡是 **~100 倍**量级差；息屏本身省电有限，真正的省电全靠 10 分钟后的 deep sleep。
- 实测法：① CW2017 SOC 1~2 小时前后差值反推（不需拆机）；② 断开电池串 µA 表；③ 带电流统计的 USB 表（仅充电通路）。
- 可继续省电的点（未实施）：息屏期间关 I2S/codec（~5~10 mA）、把 10 分钟缩到 2~3 分钟、深睡时给背光升压 IC 的 EN 脚下拉。

## 背光电路结论（查官方开源仓库）
- `github.com/folotoy/ai-passport` 只开放 `docs/hardware-design/`（规格 + 硬件开发指南 + BSP 引脚表），**没有 schematic PDF / 原理图源文件**；"OPEN HARDWARE" 是宣传口径，实际没放图。
- 官方 README 的硬件契约明确：`Display ST7789P3 ... SPI2 at 40 MHz; **LEDC backlight**`，且"GPIO18/19 are reserved for USB; the default UART0 TX on GPIO21 conflicts with the backlight"。
- 结论：背光 = **GPIO21 经 LEDC PWM 直驱**，没有独立 EN 引脚可控 → "深睡时拉低背光升压 EN"这条不成立。深睡时 GPIO21 随数字域掉电变高阻，是否微亮取决于板上驱动管极性，只能暗处实测。
- 官方低功耗 demo（`main/demo_low_power.c`）只做 RTC timer 唤醒，没有 GPIO 唤醒先例（我们的 GPIO0 深睡唤醒是自己摸的）。
